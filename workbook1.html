11:00–12:00 · Principles of Equity

KEY POINTS — Equality vs equity: equality gives everyone the same; equity gives people what they need to reach the same outcome. In health data work, equity means asking who is being left behind — and designing the analysis so the answer is visible. PROGRESS-Plus is the standard lens: Place of residence, Race/ethnicity/culture, Occupation, Gender/sex, Religion, Education, Socioeconomic status, Social capital — Plus age, disability, and other context-specific factors. Apply the lens at every stage: objectives (whose health are we measuring?), data (who is missing from the register?), analysis (disaggregate, don’t just average), reporting (show the gaps plainly), and recommendations (target the underserved). Averages hide inequity. A national TB decline can coexist with a district where cases are rising — you will see exactly this in Demoland with Westbrook district. Demoland worked example: males account for roughly 60–65% of TB notifications. An equity lens turns that statistic into questions: Are men less likely to seek care early? Are services reaching workplaces and transport hubs where men cluster? Your recommendations should answer those questions, not just report the share.

14:00–15:00 · Establish data analysis objectives

KEY POINTS — Every analysis starts before the data: with a written objective. Analyses that start with “let’s see what the data says” produce unfocused reports nobody uses. A strong objective names the health issue, the population, the place, the time period, and the measure: “Estimate annual TB notification rates per 100,000 by district and sex, Demoland, 2021–2025.” Work backwards from the decision: What policy question must this answer? Each objective should map to one results section and at least one recommendation. Exercise 1.1: Clean the messy DHIS2 malaria extract (60 minutes)

Purpose: Practise a systematic, documented data-cleaning workflow on a realistic messy extract, so that every downstream rate, table, and map rests on data you can defend.

Open: DA-TOT_Exercise_Messy-DHIS2-Extract.xlsx — start with the README sheet, then work in Messy_Data.

Log sheet: DA-TOT_Exercise_Messy-DHIS2-Extract.xlsx — sheet Cleaning_Log (template provided).

Steps

  1. 1. Read the README sheet. Note the file’s grain: monthly malaria reports from 6 facilities, 2024–2025, about 300 rows. The columns are Facility, District, Month, Year, Sex, Age_Group, Malaria_Cases, and Malaria_Tests (row 1 is a banner — the headers are in row 2). Note which columns are required and which must be numeric.
  2. 2. Protect the original. Right-click the Messy_Data tab → Move or Copy → tick “Create a copy” → rename the copy Messy_Data_ORIGINAL. Do all cleaning on Messy_Data, never on the original.
  3. 3. Set up your Cleaning_Log. The template has columns Step_No | Issue_Found | Rows_Affected | Fix_Applied | Excel_Feature_Used, and Step 1 (duplicate rows) is already completed as an example. You will add at least 11 more rows — 12 documented fixes minimum, one per issue type below.
  4. 4. Hunt down and fix each of the 12 planted issue types: (a) Duplicate rows — select the data → Data → Remove Duplicates; record how many rows were removed. (b) Inconsistent district spelling and capitalization (e.g. “westbrook”, “WestBrook ”, “WESTBROOK”) — standardize every value to the 12 official district names (Northfield, Eastvale, Westbrook, Southgate, Lakeside, Hillcrest, Riverside, Meadowlands, Stonebridge, Fairview, Oakdale, Pinehurst) using Find & Replace or PROPER() plus manual checks. (c) Leading/trailing spaces in text fields — apply =TRIM() in a helper column, paste back as values. (d) Mixed date formats (text dates, dd/mm/yyyy vs mm/dd/yyyy confusion) — convert the whole column to true Excel dates (yyyy-mm-dd); use DATEVALUE() or Text to Columns for text dates, and verify century/month-day order row by row. (e) Missing (blank) values in required fields — filter for blanks, decide a rule (e.g. exclude from numerators, never silently fill), and document the rule. (c–e are the classic trio: fix them before anything else.) (f) Text strings in numeric fields (“N/A”, “unknown”, “-”) — replace with blank (missing) or a documented code, never with zero unless zero is truly meant. (g) Negative counts in fields that cannot be negative — filter for <0, investigate, and recode as missing with a log note. (h) Inconsistent sex labels (M, F, Male, Female, m, f) — standardize the whole column to “Male”/“Female”. (i) Inconsistent facility names (spelling variants of the same 6 facilities) — standardize; check with a pivot table count per facility afterwards. (j) Implausible out-of-range values (e.g. a monthly case count far beyond any plausible value for one facility) — flag as “verify with source” rather than deleting. (k) Merged header cells and stray blank rows/columns — unmerge all, give every column a single-row header, delete fully blank rows/columns. (l) Numbers stored as text (green triangle in the cell corner) — convert to values (Text to Columns → Finish, or Paste Special × 1).
  5. 5. Verify with a pivot table. Insert → PivotTable on the cleaned data: count rows by facility and by month. Totals should look plausible and complete for 2024–2025 — no facility should vanish.
  6. 6. Complete the Cleaning_Log. Every fix gets a row: where, what the issue was, and exactly what you did. A log someone else could audit is the pass mark.
  7. 7. Save a cleaned copy. File → Save As → DA-TOT_Exercise_Messy-DHIS2-Extract_CLEANED.xlsx in the same folder. Keep the original file untouched. Expected output: A cleaned Messy_Data sheet (single-row headers, no merged cells, consistent districts/facilities/sex labels, true dates, numeric fields numeric, no duplicates, no negatives) plus a Cleaning_Log with at least 12 documented fixes, and a verification pivot table.

16:00–16:30 · Combining data sets in Excel

KEY POINTS — Counts alone mislead: a district with more cases may simply have more people. Combining case data with population denominators is what turns counts into comparable rates. XLOOKUP is the modern Excel lookup: =XLOOKUP(lookup_value, lookup_array, return_array). It searches left-to-right or right-to-left, defaults to exact match, and lets you specify what to return when there is no match. Build a single lookup key on both sides (e.g. District & “|” & Year & “|” & Sex) so one formula matches district, year, and sex together — this avoids the classic error of attaching the wrong year’s population. Wrap lookups in IFERROR to handle missing combinations explicitly, e.g. =IFERROR(XLOOKUP(...), “CHECK”), then investigate every “CHECK” instead of letting a silent zero through. District names must match character-for-character between files — which is exactly why you standardized spellings in Exercise 1.1.

Exercise 1.2: Combine TB notifications with census denominators (XLOOKUP) (30 minutes)

Purpose: Attach the correct population denominator to every TB notification record, producing an analysis-ready file for Day 2’s rate calculations.

Cases: DA-TOT_Demo_TB-Register_2021-2025.xlsx — sheet Data (read README and Data_Dictionary first).

Denominators: DA-TOT_Demo_Census-Population.xlsx — sheet Population.

Steps

  1. 1. Open both files and inspect. In the TB register’s Data sheet, identify the District, Year, Sex, and Age_Group columns — and note the built-in Population column (age-group populations, useful later for validation). In the census file’s Population sheet, confirm it holds official population by district × sex × year for 2021–2025 (columns District, Year, Sex, Population).
  2. 2. Add a lookup key in the TB file. Insert a column “Key_TB” with =District&“|”&Year&“|”&Sex (adjust to your actual column letters). Fill down.
  3. 3. Add the same key in the census file. Insert a column “Key_Pop” built identically: district, year, sex in the same order with the same separator.
  4. 4. Pull the census population across. In the TB file add a column “Census_Pop” with =IFERROR(XLOOKUP(Key_TB, Key_Pop_range, Population_range), “CHECK”). Fill down.
  5. 5. Investigate every “CHECK”. A missing match means a spelling mismatch or a genuinely absent combination — fix the cause, don’t overwrite the formula.
  6. 6. Spot-check five rows by hand. Pick five diverse rows (different districts, years, sexes) and confirm the Census_Pop value matches the census sheet manually.
  7. 7. Validate against the built-in figures. In a quick pivot, sum the TB file’s built-in age-group Population by district × year × sex and compare with Census_Pop: the two should agree closely. Investigate any district-year-sex where they don’t — that disagreement is exactly the kind of denominator problem this exercise trains you to catch.
  8. 8. Save your work. Save the TB file under a new name, e.g. DA-TOT_Demo_TB-Register_2021-2025_WITH-POP.xlsx, so the distributed original stays pristine. Expected output: A TB dataset in which every notification record carries its matching official census population (Census_Pop), with zero unresolved “CHECK” values, a validation note comparing Census_Pop against the summed age-group populations, and a short note of your five spot-checks.

11:00–12:00 · Accessing and using census data to calculate rates in Excel

KEY POINTS — Counts vs rates: a district with 500 TB notifications is not necessarily worse off than one with 200 — it may simply have more people. Rates divide by the population at risk so places become comparable. The rate formula: Rate = (Number of events ÷ Population at risk) × Multiplier. For TB notifications the standard multiplier is 100,000: “TB notification rate per 100,000 population”. Match numerator to denominator exactly: same place, same period, same sex and age breakdown. A 2025 district rate needs the district’s 2025 population — not the national total, not last year’s figure. Census files give you denominators: the Population sheet of DA-TOT_Demo_Census-Population.xlsx holds population by district × sex × year (2021–2025); Age_Structure gives age-group shares for age-specific rates. Small populations produce jumpy rates: a single extra case in a tiny district swings the rate wildly — flag uncertainty rather than ranking small districts precisely. Rates reveal what counts hide: compute Demoland’s district rates and the Westbrook story becomes sharper — is its rise just population growth, or a true increase in risk?

Exercise 2.1: Calculate TB notification rates per 100,000 (Tasks 1–5) (60 minutes)

Purpose: Turn raw TB notification counts into comparable district, sex, and yearly rates using census denominators — the core analytical move of the week.

Workbook: DA-TOT_Exercise-Workbook_Day2.xlsx — start with the README sheet; data are in TB_Data (district × year × sex, 120 rows) and Census_Data; complete Tasks 1–5 on the Tasks sheet; check yourself afterwards in Answer_Key.

Steps

  1. 1. Read the README sheet end-to-end. Note the learning objectives and the instruction to build formulas that reference TB_Data and Census_Data — never type values by hand. Do not peek at Answer_Key until you have attempted every task.
  2. 2. Inspect TB_Data and Census_Data. Confirm the shared keys: District, Year, Sex. TB_Data holds TB_Cases_Notified (and Treatment_Success counts for later); Census_Data holds the matching populations.
  3. 3. Task 1 — district rates, 2025. For each of the 12 districts compute =SUMIFS(TB_Data cases, district, 2025) ÷ SUMIFS(Census_Data population, district, 2025) × 100000. Format with one decimal place.
  4. 4. Task 2 — rates by sex, 2025. Same formula with a Sex criterion (Male, then Female). Compare the two: does the male rate exceed the female rate, consistent with the documented higher male burden?
  5. 5. Task 3 — national trend, 2021–2025. SUMIFS on the Year column only (all districts, both sexes) for each year, divided by the matching national population. Describe the trend in one sentence on the Tasks sheet.
  6. 6. Task 4 — highest district, 2025. Use MAX on your Task 1 rates and return the district name (INDEX/MATCH). Record it.
  7. 7. Task 5 — the rising district. For each district compute percent change = (2025 rate − 2021 rate) ÷ 2021 rate. One district rises while all others fall — name it, and write two sentences on whether its rising case counts reflect a rising rate or just population change.

12:00–13:00 · Descriptive statistics review

KEY POINTS — Central tendency: the mean (average) uses every value but is dragged by outliers; the median (middle value) resists outliers; the mode (most common) suits categories. Report the median alongside the mean whenever data are skewed. Spread matters as much as centre: range (max−min) is quick but fragile; the standard deviation (SD) measures typical distance from the mean; percentiles (e.g. the 25th and 75th) show where the bulk of values sit. Shape: in right-skewed data (a few very high districts) the mean exceeds the median — a signal to investigate the high outliers rather than report the mean alone. Choose deliberately: summarize symmetric data with mean ± SD; skewed data with median and interquartile range; categorical data with counts and percentages (always with denominators). Descriptive statistics describe — they do not explain. “Westbrook’s rate is the highest” is a description; “why” needs further analysis.

KEY POINTS — Excel’s core functions: AVERAGE, MEDIAN, MODE.SNGL, STDEV.S (sample) vs STDEV.P (full population), MIN, MAX, QUARTILE.INC, PERCENTILE.INC, COUNT. 9:30–10:30 · IMRAD Structure

KEY POINTS — IMRAD = Introduction, Methods, Results, and Discussion — the international standard skeleton for analytical reports. Readers know exactly where to look for each kind of information. Introduction: why this analysis was done — background, the policy problem, and the 3–5 analysis objectives. Ends where the data begins. Methods: what you did, in enough detail to reproduce — data sources (file names, periods, coverage), cleaning steps (cite your Cleaning_Log approach), how rates and statistics were calculated, and limitations (e.g. Riverside’s incomplete mortality registration). Results: what you found — text plus tables, figures, and maps. No interpretation here, just findings in logical order (national picture first, then disaggregated). Every table/figure is numbered, titled, and referenced in the text. Discussion: what it means — interpret findings, compare with expectations, acknowledge limitations, and lead into recommendations. This is where the equity lens speaks loudest. Front matter: a one-page executive summary (objectives, key findings, recommendations — written last) and a table of contents. Back matter: annexes with detailed tables and the data dictionary. Your team report (4–6 pages) will follow IMRAD exactly — assign each section an owner today.

11:00–12:00 · Best practices for creating tables

KEY POINTS — One table, one message. If you need two messages, you need two tables. Every table needs: a number (Table 1, 2, 3…), a self-contained title stating what, where, and when (“TB notification rate per 100,000 by district, Demoland, 2025”), and units in the column headers — never buried in a footnote hunt. Numbers: right-align, use consistent decimal places (one decimal for rates, whole numbers for counts), and use thousands separators. Never show four decimals on a count of people. Structure: no vertical text, no merged header cells, minimal gridlines (header rule + bottom rule is enough), zebra shading only if it aids reading — never rainbow fills. Sort with intent: by magnitude (highest rate first) when ranking matters, chronologically for trends, alphabetically only when readers must find one row fast. Footnotes explain: definitions (e.g. “treatment success = cured + treatment completed”), data sources, and symbols. Denominators belong in the table or its notes — a percentage without its denominator is unverifiable. Design for the reader who photocopies in black and white: if the table only works in colour, it doesn’t work.

14:00–15:00 · Best practices for creating figures

KEY POINTS — Choose the chart for the message: trends over time → line chart; comparisons across districts → horizontal bar chart; composition of a whole → stacked bar (use pie only for 2–3 slices, never 3D); distribution → histogram. Bar and column charts must start the value axis at zero — truncating the axis exaggerates differences and is the commonest form of visual dishonesty. Write the takeaway in the title: “TB notifications fell nationally but rose in Westbrook, 2021–2025” beats “TB notifications by district”. A reader skimming titles should get the story. Label directly where possible (data labels on the line/bar ends) instead of forcing readers to bounce between legend and chart. Keep legends only when direct labelling clutters. Colour with restraint: one accent colour for the story’s focus (e.g. Westbrook’s line), grey for context; avoid red-green pairings (colour blindness); ensure the figure survives black-and-white printing. Declutter ruthlessly: remove gridlines or fade them, delete chartjunk (3D effects, shadows, background images), and put the data-ink ratio to work — every pixel should carry information. Every figure needs: a number (Figure 1, 2…), the takeaway title, axis labels with units, and a source note. Reference each figure in the results text (“Figure 2 shows…”).

KEY POINTS — Maps answer “where” at a glance: a district choropleth (areas shaded by value) makes geographic inequity instantly visible — Westbrook’s rise and Riverside’s gaps literally stand out. Glossary of Key Terms

The working vocabulary of the week. Starred terms () appear in the Formula Quick-Reference.*

Term Definition
Age group Population band used for disaggregation (here: 0–14, 15–24, 25–44, 45–64, 65+). Never collapse into “adult” without justification.
Cascade training TOT model in which trainees become trainers, passing skills to successive cohorts. Fidelity to the original materials protects quality.
Cell reference (absolute vs relative) A1 adjusts when filled down; $A$1 stays fixed. Use absolute references for multipliers and denominator cells reused across rows.
Choropleth map Map in which areas are shaded by value bands. In this course, built as a tile-grid map with conditional formatting.
Cleaning log Row-by-row record of data-quality issues found and fixes applied — the audit trail of Exercise 1.1 and of any real analysis.
Completeness Data-quality dimension: are all expected records present? (Riverside’s mortality file is the course’s deliberately incomplete example.)
Consistency Data-quality dimension: do values follow the same codes, spellings, and formats throughout?
CRVS Civil registration and vital statistics — the system recording births, deaths, marriages, and divorces; the backbone of mortality statistics.
Data dictionary Document defining every variable: name, definition, codes, units, missing-value conventions. Read it before touching the data.
Denominator The population at risk that a count is divided by to form a rate. Must match the numerator on place, period, sex, and age.
Descriptive statistics Numbers that summarize data: centre (mean, median, mode), spread (range, SD, percentiles), and shape (skew).
DHIS2 District Health Information Software 2 — the open-source platform many countries use for routine health facility reporting.
Disaggregation Splitting results into subgroups (district, sex, age). Averages hide inequity; disaggregation reveals it.
Equity (health) Everyone having a fair opportunity to attain full health — which may require unequal effort and resources. Contrast equality (the same for all).
Executive summary One-page standalone synopsis: objectives, headline findings with numbers, recommendations. Written last, read first.
IMRAD Introduction, Methods, Results, and Discussion — the standard structure for analytical reports.
Incidence New cases occurring in a population over a period. (TB notification rates approximate incidence as captured by the system.)
Interquartile range The range from the 25th to the 75th percentile — the spread of the middle half of the data; robust to outliers.
Mean Arithmetic average: sum ÷ n. Sensitive to outliers and skew.
Median The middle value when data are ordered. Resists outliers; preferred for skewed distributions.
Metadata Data about data: source, coverage, collection method, definitions, known limitations.
Mortality rate Deaths ÷ population at risk × multiplier, for a defined cause, place, and period. Meaningless where registration is incomplete.
Numerator The count of events (cases, deaths) that forms the top half of a rate.
Percent change ((New − Old) ÷ Old) × 100. Use for trends; always state the baseline.
Pivot table Excel’s drag-and-drop summarization tool: rows, columns, values, and filters that rebuild instantly as questions change.
PROGRESS-Plus Equity lens: Place, Race/ethnicity, Occupation, Gender/sex, Religion, Education, Socioeconomic status, Social capital — Plus age, disability, and context-specific factors.
Rate (Events ÷ population at risk) × multiplier (e.g. per 100,000). Makes places and periods comparable.
Recommendation Evidence-linked, actionable statement of who should do what, where, by when — derived from a specific finding.
SOP Standard operating procedure — the documented rules governing data access, sharing, and handling in each country.
Standard deviation (SD) Typical distance of values from the mean. Report as mean ± SD for symmetric data.
Synthetic data Artificially generated data mimicking real structure without real records. All Demoland data are 100% synthetic.
TB notification rate Notified TB cases ÷ population × 100,000, per year. The course’s core indicator.
Timeliness Data-quality dimension: are data available soon enough to act on?
Treatment success rate (Cured + treatment completed) ÷ all notified TB cases × 100, per cohort.
Validity Data-quality dimension: do values fall within plausible ranges and formats (no negatives where impossible, no text in numeric fields)?
XLOOKUP* Modern Excel lookup: =XLOOKUP(lookup_value, lookup_array, return_array). Exact match by default; searches in any direction.
